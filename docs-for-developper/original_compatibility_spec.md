## 1. 目的と保証範囲

現在の原典ヒューリスティクス版は、θの100標本平均、学習時の未補正θ、
占有カテゴリのμの100標本平均、空カテゴリのμの一様配置を選択する。
初期化・乱数生成・通信・前処理は現行方式であり、原典全体とは異なる。
追加仕様では、これらの残る差もまとめて切り替える実行プロファイルを設ける。
初期化だけを交換して学習を現行の別乱数列で始める方式とは区別する。

目的は、INTERについて、同定した原典を現代の固定環境で動かした参照実装と、
入力、初期状態、反復途中の状態、乱数状態を照合できる実装を提供することである。
当時のPython 2環境とのビット単位の一致や、論文ARI値との一致を保証するものではない。
100標本平均は単一標本のGibbs更新と分布が異なる原典のヒューリスティクスである。

### SINGLEの扱い

著者から「INTERの原典はSINGLEの使い回しで、ヒューリスティクス等は共通のはず」
との情報を得ている。これを設計の根拠として、SINGLEにも共通の初期化・学習処理を
適用できるようにする。ただしSINGLE専用のPython 2原典は手元にない。
したがって、SINGLE版は**INTERで確認した共通処理を移した構成**と説明し、
SINGLE原典全体との照合済み実装、あるいは論文値の完全再現とは記載しない。

SINGLEではUの観測語を固定して学習する契約、語彙14、各属性のカテゴリ当たり
集中度1.0を維持する。INTERの語彙13・集中度0.1へ変更しない。
Bの存在を前提とする前処理や通信もSINGLEへ持ち込まない。
後年のSINGLEリファクタ版には異なる初期化があるが、これを失われた原典の
確定仕様とはみなさない。

## 2. 設定インターフェース

既存セクションに新しい列挙キーを1個追加する。

```yaml
original_heuristics:
  execution_profile: current  # current / original。省略時は current
  theta_mean_samples: 1
  inference_theta: rescaled
  gaussian_mean_samples: 1
  empty_component_mean: prior
```

| `execution_profile` | 意味 |
|---|---|
| `current` | 現行の初期化・前処理・独立Generator・通信方式を維持する。既存4キーの組合せは従来どおり選べる |
| `original` | 以下に定義する原典の初期化・乱数・学習計算・通信・前処理を一体として使う。SINGLEは上記の出自上の限定を伴う |

初期化、乱数API、通信順を個別のスイッチにはしない。同じ初期化でもその後に
消費する乱数列が変わるため、今回の目的である原典全体との対照を1個の設定で表す。
初期化要素ごとの探索や自由な全組合せの提供は今回の対象外とする。

原典プロファイルでは次の設定を**明示的に要求**する。自動で値を書き換えない。

```yaml
word_model:
  rescaling: legacy_theta_sum
  theta_sampler: dirichlet
  importance_candidates: 10000  # Dirichlet方式では使用しない。既存の値を保持
original_heuristics:
  execution_profile: original
  theta_mean_samples: 100
  inference_theta: raw
  gaussian_mean_samples: 100
  empty_component_mean: original_uniform
attribute_model:
  exclusivity: distinct
freeze:
  gmm: false
  theta: false
  attributes: false
```

### 検証と対応範囲

- 新キーの未知値、真偽値、数値、nullは設定エラーとする。直接dataclass構築と
  YAML読込みの双方で検証し、解決済みYAMLへ保存して再読込できること。
- `original` と上記の必須設定の不一致は、該当キーを示した設定エラーとする。
  importance方式、4キーの一部だけの有効化、freeze、属性の重複を許す方式は
  原典プロファイルでは扱わない。`current` では従来どおり扱う。
- 対応する学習は `single-csl` と `inter-csl`。INTERの原典プロファイルは
  `interaction: mh` のみ対応し、全受理・通信なしとの組合せは設定エラーとする。
  語長は両モードとも4、`kmeans_n_init` は10を要求する。
- カテゴリ数、γ、GIW事前、学習πの集中度は既存の設定値を使い続ける。
  参照実装と原典ハイパラでの照合は各属性10カテゴリで実施する。
  他の値で走ることと論文設定を再現することは区別する。
- 原典プロファイルのseedは32bit非負整数に限定し、後述の全試行seedが範囲内か
  学習前に検証する。`current` の既存seed規則は変更しない。
- CLIで学習を始める前に設定と入力を検証する。不整合設定でモデルを一部だけ
  初期化したり、値を自動補正したりしない。

## 3. 原典プロファイルの初期化

### INTERの順序

1. Aについて z → F → 内部語を初期化する。
2. Bについて z → F → 内部語を初期化する。
3. θのA全行 → B全行を初期化する。
4. KMeansと初期Σを、Aの a/p/o/c → Bの a/p/o/c の順に設定する。
5. 初期πを、Aの a/p/o/c → Bの a/p/o/c の順に生成する。

現行constructorをA・Bの順で2回呼び、最後に初期状態だけ上書きする実装には
しない。その際の余分な乱数消費も、次節の共有乱数境界に含まれるためである。
runnerから共同初期化する経路を用意し、通常のconstructorの経路を維持する。

| 項目 | 原典プロファイルでの処理 |
|---|---|
| z | 各カテゴリを `int(uniform(0, K))` で独立一様に生成する。初期πを使わない。aは文書順、p/o/cは属性ごとに文書→物体順 |
| F | `[a,p,o,c]` から `int(uniform(0, 4-n))` で順次取り除く。4番目の `uniform(0,1)` も消費する |
| 内部語 | INTERは各トークンを `choice(range(V))` で独立一様初期化する。θ・F・zからは生成しない |
| 初期θ | 各行についてγをパラメータとするDirichletを実際に100標本生成し、算術平均する。学習時のθ平均化だけで代用しない |
| 初期μ | `k-means++`、`n_init=10`、共有RandomStateを直接渡すKMeans。a/p/o/c順、p/o/cのflattenは文書→物体順。別の整数seedを引かない |
| 初期Σ | 全属性・全カテゴリで `0.05 I`。GIW事前の `covariance_scale`（例では0.01）とは別の値であり、その設定値を書き換えない |
| 初期π | 原典の採用分岐であるGEM型stick-breaking。`b ~ Beta(1, 1, size=K)`、`p = b * [1, cumprod(1-b[:-1])]`、最後に全K成分を総和で正規化する。最終成分を残余で置き換えない |

初期πのBetaの第2パラメータ1は、確認した原典の初期化定数である。
原典プロファイルではSINGLEにも共通のこの初期化を採用するが、学習πへの加算値は
SINGLEで1.0、INTERで0.1のまま維持する。初期πのGEM強度と学習πの集中度を
暗黙に同一視しない。SINGLEのこの採用は共通初期化という著者情報に基づく設計で、
未入手のSINGLE原典から直接確認した値とは記載しない。

INTERの語IDは0〜V-1の正規順とする。原典では初期語に現れたIDからθの列を
構成し、その後はIDを列indexとしても使っている。全IDが初期語に現れなかった
場合は、原因とseedを示して停止する。語を追加したり、再抽選して試行を
成功させたりしない。これは原典の未定義的な欠落ケースを明示的に拒否する処理である。

### SINGLEへの共通処理の適用

Uだけについて z → F → θ → KMeans/Σ → π の順とする。
内部語には既存の観測コーパスをそのまま使い、INTERの一様語を生成しない。
このための未使用の語抽選も消費しない。コーパスの語彙対応は既存の読込みに従う。
語彙数と観測コーパスの実効語彙の整合性を検証する。

初期θ100、初期Σ0.05、GEM初期π、一様z、Fの生成方法、KMeansの乱数は
INTERと共通にする。触覚を含むUの既存の観測次元は維持する。
この1主体への適用順は本仕様の定義であり、SINGLE専用原典で照合した順序ではない。

## 4. 乱数の寿命・抽選API・通信

### 乱数

- 試行番号を0始まりの `experiment_id` とし、原典プロファイルの実効seedを
  `run.seed + experiment_id` とする。0以上 `2**32-1` 以下を要求し、折り返さない。
  `seed: 0` の10試行は、既存の原典参照実験と同じ0〜9になる。
- 試行ごとにローカルな `numpy.random.RandomState(seed)` を1個生成する。
  INTERはA/B、NumPy、SciPy、KMeansがこの同じオブジェクトを使い、初期化から
  学習終了まで連続消費する。途中で再seedせず、A/Bへspawnしない。
- SINGLEも同じ規則の1個のRandomStateを使う。観測語の読込みには乱数を使わない。
- グローバルな `np.random` やPythonの `random` の状態を変更しない。
  独立した試行の逐次実行・別プロセス実行で同じ結果になること。
- 原典の `multinomial(1,p)`、一様抽選、Dirichlet、Beta、逆Wishart、Normalの
  APIと呼出し順を再現する。Generatorの `choice(p=...)` へ置換しない。
  種類の異なる乱数器を無理に同一型として扱わず、必要な呼出しを明示する。
- 原典の `np.random.seed()` はOS由来のseedで、当時のseedは復元できない。
  明示seedは今回の検証のための規約であり、論文実験の乱数列を復元したとは言わない。

### INTERの半ターン

```text
現在のBから提案語を新たに生成 → AでMH受理 → Aを学習更新
更新済みAから提案語を新たに生成 → BでMH受理 → Bを学習更新
評価・保存（乱数を消費しない）
```

初回のB→Aも、初期内部語のコピーではなく別の提案語を生成する。
受信直前にだけ提案を引き、最後のB更新後に未使用の提案語を生成しない。
各半ターンの語生成・MHには、その時点の補正θを使う。後半のAは更新済みであり、
補正前後のθを古いまま使う仕様にはしない。
MHで受理率が1以上でも、原典と同じく各トークンの一様乱数を消費する。

SINGLEは通信を行わず、観測語を固定してUを1回更新することを1反復とする。

## 5. 学習計算と数値演算

両モードとも更新順は `z → π → Gaussian → F → θ`。
属性内のカテゴリ・文書・物体・語の走査順も原典に合わせる。
z/F推定には補正前θを使い、語生成・MHには補正θを使う。

| 対象 | 原典プロファイルの規約 |
|---|---|
| z | a/p/cは `π × 必要な語尤度 × Gaussian.pdf` を直接計算・正規化し、oは原典のlogpdf/logsumexpを用いる。a/p/o/cの順に `multinomial(1,p)` で抽選する |
| π | 全物体を含むカテゴリ数に、設定されたカテゴリ当たり集中度を加えたDirichletから**1標本**を生成する。πの100標本平均は行わない |
| 占有カテゴリのGaussian | 中心化したscatterによりGIW事後を計算し、Σを逆Wishartから1標本、条件付きNormalからμを実際に100標本生成して平均する |
| 空カテゴリのGaussian | μの各座標を先に一様生成（pは[-0.5,0.5)、a/o/cは[0,1)）、次にΣをGIW事前の逆Wishartから1標本生成する |
| F | a/p/o/cの全順列を原典順で列挙し、補正前θの直接積を正規化して `multinomial(1,p)` で抽選する |
| θ | 更新後のFと内部語／観測語から数えた各行の事後Dirichletを実際に100標本生成して平均する |
| θ補正 | 原典の列和・除算・行正規化の演算順を使う。補正θは保存されたraw θを破壊的に変更しない |

これらの直接積・演算順は数理上等価な現行の対数計算やGIW式でも、丸めと
抽選結果の境界が変わり得るため互換経路で揃える。通常経路は変更しない。
確率の非有限値、総和0、非正定な事後行列等が生じた場合は、試行・反復・主体・
属性等を示して停止し、別アルゴリズムへの自動フォールバックや再抽選をしない。

照合相手は、既存監査で使用した「現代Pythonへ移した原典」とする。
この参照実装は100回のNormal呼出しを `size=100` の一括抽選へ置換している。
今回もその方式を固定し、参照と同じ標本・平均・RNG境界になることを検証する。
Python 2原文の100個の逐次呼出しとのビット単位一致までは保証しない。
Dirichletの平均や総和も含め、演算順と差分を検証記録に残す。

## 6. 前処理とデータの出自

### INTER

原典のdata_readを含む比較とする。legacy datadumpから両主体を読み、
従来どおり対象30場面を選択した上で、**AとBの動作の先頭3列をBの最小値・最大値で
正規化する原典の挙動**を原典プロファイルに限り再現する。
それ以外の動作処理、位置・形状・色、注意対象、物体順、正解ラベルを変更しない。
正規化の対象段階・最小最大値の算出範囲・定数列の扱いは原典readerとの
全値比較で確認し、主体別に正規化済みのAから逆算しない。

この挙動は移植時に改善された処理を、比較のために意図的に戻すものである。
現行方式の方が合理的と考えるという著者の見解は維持し、原典方式の方が
推奨される一般的な前処理だとは説明しない。

原典プロファイルのINTERは元のlegacy datadumpを必要とする。
前処理前の情報がないcompact `agentA.npz` / `agentB.npz` だけの入力は
原典readerとの同一性を保証できないので、理由を示して検証エラーとする。
両形式が存在する場合、原典プロファイルではlegacy側を明示的に選び、
実際に使用した入力形式を記録する。通常プロファイルのNPZ優先順位は維持する。

### SINGLE

Bの極値を使う処理を導入せず、U単独の現在の前処理とコーパスの読込みを維持する。
compact入力も従来どおり使える。SINGLE固有の原典readerは未確認であるため、
ここは原典前処理との一致を保証する対象外であることをREADMEにも記載する。

### CLI間の整合性

`validate-data`、`learn`、`analyze`、INTERの `predict` で、同じ設定から同じ
処理済み観測が得られるようデータ選択を共有する。学習だけ別の正規化にしない。
正解データは既に著者確認済みの論文で使ったものを引き続き使う。
原典コードを実行時に参照したり、兄弟リポジトリを本番依存にしたりしない。

## 8. 実装境界・保存・予測

- `config.py` に設定・組合せ検証、runnerに原典用の初期化・試行乱数・通信経路、
  model/GIW/属性抽選/補正に必要な互換計算を追加する。
  元のPython 2ソースのexec、lib2to3、調査adapterを本番で呼ばない。
- 既存のconstructor・学習経路を維持し、無効時に初期状態、配列、メタデータ、
  RNGを変えない。`current` と4機能有効の構成も現行B2実装と一致させる。
- 原典プロファイルのINTER初期化は、両主体を受け取る専用の内部factory等で
  行う。共同初期化を満たせない単独constructor呼出しは明示的に拒否し、
  余分な通常初期化をした後に状態を差し替えない。
- checkpointの配列形式・既存の読込み互換性、反復CSVと解析出力を維持する。
  学習方式は解決済み設定と別の出自記録で判別可能にする。
  旧checkpointだけから新しい方式を推定したり、学習再開機能を追加したりしない。
- 出自記録には実効profile、seed規則・実効seed、入力形式とハッシュ、
  パッケージ・ライブラリ版、SINGLE/INTERの保証範囲を記す。
  検証時は共有RNGの初期化終了・半ターン境界も保存する。
- INTERの予測は保存した状態を使う既存の条件付き予測とし、予測アルゴリズム・
  予測seedの方式を原典予測コードへ交換しない。入力前処理は学習と揃える。
  **原典互換という保証は学習実行に対するもので、原典の予測プログラム全体には
  拡張しない。** SINGLEの予測非対応も従来どおりとする。

1. 基準コミット `455b499` と、新キー省略・`current` 明示の両方を別プロセスで
   比較する。通常設定の両モード、importance/Dirichletと既存補正方式、および

   seed範囲と加算overflow、対応しない通信・入力を個別に検証する。

### 9.2 原典INTERとの独立照合

1. 原典3ソースと、固定した翻訳・現代化規則から参照実装を作る。
   本番のサンプリング関数を借りない独立経路とする。
