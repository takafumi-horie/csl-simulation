# 原典実装と現行実装の違い

本資料は、論文実験の再現や後続研究で本リポジトリを利用する方に向けた比較である。
主な対象は **Inter-CSL-PGM（INTER）**。原典コード・通常版・原典互換版の違いと、
比較結果から確認できたことを整理する。開発者向けの仕様・検証資料は
`docs-for-developper/` に別途保存している。

原典のヒューリスティクスの採用を検討する際は、
[README末尾の著者NOTE](../README.md#author-note)も参照されたい。
原典との実行結果の一致と、確率モデルに対する推論の数学的整合性は分けて扱う。

## 比較対象

| 呼び方 | 内容 |
|---|---|
| 原典実装 | 論文実験で使用した系統の、保存されたPython 2学習コード |
| 固定原典参照 | 原典を固定した現代Python・数値ライブラリ環境で動作させた検証用実装。seed明示、KMeansの設定固定等の変換を含む |
| 通常の現行実装／通常版 | [inter.yaml](../examples/inter.yaml)の学習方式。`execution_profile: current`、追加4ヒューリスティクスは既定値で無効 |
| 従来の4機能版 | 通常版の初期化・前処理・乱数・通信を維持し、後述の4ヒューリスティクスを有効化した構成 |
| 原典互換版 | [inter_original_heuristics.yaml](../examples/inter_original_heuristics.yaml)。`execution_profile: original` で初期化・学習・前処理・乱数・通信を揃えた構成 |

以下の表の「現行」は、特記しない限り**通常版**を指す。現在のコードでもオプションにより
原典の処理を選べるため、「現行コードでは原典の処理を実行できない」という意味ではない。

記号は、θがカテゴリごとの語確率、zがカテゴリ割当、Fが各語の指す属性、
πがカテゴリ混合比、μ・Σが各カテゴリの特徴の平均・共分散を表す。
特徴の属性は動作a・位置p・形状o・色cである。

## 1. ハイパーパラメータ

調査開始時のINTER設定には、原典との次の相違があった。

| 項目 | 原典のINTER | 調査開始時の設定 | 現在の通常INTER設定例 |
|---|---:|---:|---:|
| 混合比のカテゴリ当たり集中度（α/K） | 0.1 | 1.0 | 0.1 |
| 語彙数 | 13 | 14 | 13 |

原典のINTERは各属性K=10、α=1で、各カテゴリの事後カウントへの加算値が0.1となる。
調査では特に混合比の集中度が色ARIに影響することが確認され、初期の食い違いの
主要因と考えている。ただし、ハイパラを揃えた後も学習・初期化等の差は残っていた。

YAMLの対応は以下のとおり。

```yaml
hyperparameters:
  vocabulary_size: 13
  gmm:
    mixture_concentration: {a: 0.1, p: 0.1, o: 0.1, c: 0.1}
```

**設定例の修正と、キー省略時の既定値は別である。** スキーマの省略時既定値は、
語彙14・混合比のカテゴリ当たり集中度1.0のままなので、独自YAMLでは明示指定を確認する。
SINGLEの設定例はその論文条件として語彙14・集中度1.0を維持しており、
INTERの13・0.1へ変更する対象ではない。

## 2. 学習方法・ヒューリスティクス

| 項目 | 原典 | 通常の現行実装 |
|---|---|---|
| θの更新 | 事後Dirichletの100標本平均 | `legacy_importance`：Dirichletから生成した候補を、補正に対応する重要度で選択。既定10,000候補 |
| z・F推定に渡すθ | 補正前のθ | 補正後のθ |
| 占有カテゴリのμ更新 | Σを生成し、条件付きNormalの100標本を平均 | Σを生成し、条件付きNormalから1標本 |
| 空カテゴリのμ | 各座標を一様配置。pは[-0.5,0.5)、a/o/cは[0,1)。その後に事前逆WishartからΣを生成 | GIW事前に従ってΣと条件付きμを生成 |

原典も現行も、語生成とMH受理には補正後のθを使う。
原典の補正は発話だけに使うわけではなく、MH受理にも使う点に注意されたい。
今回の4語・4属性の全順列を使うF推定では、固定z・θの下で補正因子が相殺する。
zへの作用とFへの直接作用を同じものとは扱わない。

学習中のπは、原典も現行も**事後Dirichletの1標本**である。
原典にあるπの100標本平均の記述は、実験で採用されていない別の初期化分岐であり、
今回比較する学習処理ではない。

通常のimportance方式と原典の学習順は `z → π → Gaussian → F → θ`。
通常版で単純に `theta_sampler: dirichlet` に変更すると、θは1標本で、
Gaussian後の順序も `θ → F` となる。原典のθ100標本平均・`F → θ` とは一致しない。

100標本平均は、単一標本の計算精度を高めるだけの処理ではなく、更新分布を変える。
条件付きNormal分布を固定すれば、100個の独立なμ標本の平均は1標本に比べて
分散が1/100になる。Dirichlet標本の平均も、元の単一Dirichlet標本とは異なる。

これらの数理上の懸念と研究上の採用判断については、
[著者NOTE](../README.md#author-note)にまとめている。

## 3. 初期化

| 項目 | 原典 | 通常の現行実装 |
|---|---|---|
| 初期π | GEM型stick-breaking。Beta(1,1)の切断した重みを全成分で再正規化 | 対称Dirichlet |
| 初期z | 各カテゴリを一様に抽選し、初期πを使わない | 初期πに従って抽選 |
| 初期θ | 事前Dirichletの100標本平均 | 事前Dirichletの1標本 |
| 初期Σ | 全属性・全カテゴリで0.05I | 設定されたスケール。設定例では0.01I |
| 初期μ | 共有RandomStateを直接使うKMeans | 属性ごとに生成した整数seedを使うKMeans |
| 初期F | 属性を順に取り除いて抽選し、最後の1択でも乱数を消費 | 重複なしの一括抽選 |
| 初期内部語 | 語彙から独立一様に生成 | 初期θ・z・Fから生成 |
| A/Bの順序 | Aのz/F/語、Bのz/F/語、θのA/B、KMeansのA/B、πのA/B | Aの初期化全体を終えてからBを初期化 |

初期Σの0.05Iは、GIW事前のスケールV₀=0.01Iとは別の量である。
初期θの100標本平均と、学習θの100標本平均も別の処理となる。

「初期化の差」には複数の分布・生成順・乱数消費の差が含まれる。
初期化全体を変えた実験結果から、個々の要素の寄与までは特定できない。

## 4. 乱数・通信・数値計算

| 項目 | 原典 | 通常の現行実装 |
|---|---|---|
| 乱数生成器 | A/Bで共有するMT19937。初期化から学習へ連続消費 | 試行からA/Bへ派生する独立PCG64 |
| z・Fの離散抽選 | `multinomial(1,p)` | `choice(p=...)` |
| 提案語の生成時点 | 各受信直前に新たに生成 | 更新後に生成し次の受信まで保持。初回は初期内部語を流用 |
| 最終B更新後 | 未使用の提案を生成しない | 次回用の提案を生成する |
| 尤度計算 | a/p/cは直接確率積、oは対数計算 | 全属性を対数で計算 |
| GIW事後の計算 | 中心化scatterの式 | 代数的に等価な非中心化二次モーメントの式 |
| θ補正の総和等 | 逐次和など原典の演算順 | NumPyの集約等による演算順 |

KMeans自体は両者とも使っているが、渡す乱数とその消費順は異なる。
同じ正規化確率なら離散抽選の分布は同じでも、APIが違えば乱数軌道は一致しない。
同じseed番号だけでは同じ実験にはならず、演算順による丸め差も、その後の抽選を
分岐させる可能性がある。これらが単独で系統的な性能低下を起こすとは断定していない。

初回以降の提案cacheは、話者の状態が保持中に変わらなければ条件付き提案分布が
対応する。ただし、初回の提案と共有乱数の消費時点まで同一という意味ではない。
原典も両方向の通信直前に補正θを計算しており、古いθを使い続ける問題ではない。
MH受理率が1以上でも各トークンで一様乱数を引く処理は両者に共通する。

原典互換版はローカルなRandomStateを共有し、グローバル乱数を変更しない。
seed規則は検証用に `run.seed + experiment_id` と定義している。
原典のOS由来seedや、当時のPython 2・ライブラリ・BLAS環境は復元したものではない。

## 5. データ・前処理

**位置・形状・色の入力特徴はA/Bとも原典と全値一致し、正解データも論文使用と同一**
である。確認された前処理の相違は、Aの**動作特徴の先頭3次元**の正規化にある。

| 対象 | 原典 | 通常の現行実装 |
|---|---|---|
| Aの動作特徴の先頭3次元 | Bの最小・最大値を使用 | A自身の最小・最大値を使用 |
| Bの同じ特徴 | Bの最小・最大値を使用 | Bの最小・最大値を使用 |

著者としては、各主体を自身の値域で正規化する**現行の前処理の方が合理的と
考えられるが、論文実装とは若干異なる**と考えている。
変更箇所が限定されることと、結果への影響が常に小さいことは同義ではない。
動作の変化がカテゴリや通信を通じて、他属性・他主体へ間接的に影響する可能性もある。

原典互換版は比較のため、AにもBの値域を使う処理を意図的に再現する。
この処理には正規化前のlegacy datadumpが必要で、compact NPZだけでは受け付けない。
一般的な前処理としてBの値域を使う方法を推奨するものではない。

## 6. ARIの集計

| 項目 | 保存された原典の評価コード | 現行の標準評価 |
|---|---|---|
| 位置・形状・色 | 全55物体 | 各場面の注意対象30物体 |
| 動作 | 30場面 | 30場面 |

これは学習カーネルの差とは別の論点である。原典互換プロファイルを選んでも、
本番の標準ARIは注意対象で計算する。比較報告では全物体のARIも独立計算して併記した。
論文表がどちらの物体集合・A/Bの集約方法を使ったかは未確定である。
正解データが同じでも、評価対象が異なればARIは変わる。

## 実行方法と検証結果

通常版は `examples/inter.yaml`、原典互換版は
`examples/inter_original_heuristics.yaml` を指定して実行する。
原典互換版のYAMLは、θのDirichlet方式と4機能に加えて、次を指定している。

```yaml
original_heuristics:
  execution_profile: original
  theta_mean_samples: 100
  inference_theta: raw
  gaussian_mean_samples: 100
  empty_component_mean: original_uniform
```

**以前の4機能だけの構成**へ戻す場合は、同じYAMLで `execution_profile: current` とする。
他の4キーは維持する。これらの設定例は[READMEの実行例](../README.md#quick-start--クイックスタート)
からも参照できる。

原典互換版のINTERを10試行・各500反復で実行したところ、固定原典参照の全20最終状態に
ついて、保存形式を対応付けた400配列項目と、独立計算したARI160値が完全一致した。
以下は注意対象のARI、平均±標本標準偏差（n=10）である。

| 属性 | 原典互換版A＝固定原典参照A | 原典互換版B＝固定原典参照B | 論文Table 3 |
|---|---:|---:|---:|
| 動作 | 0.304404 ± 0.061005 | 0.336771 ± 0.050998 | 0.309 |
| 位置 | 0.766372 ± 0.108540 | 0.693426 ± 0.120847 | 0.794 |
| 形状 | 0.305723 ± 0.149854 | 0.324951 ± 0.083312 | 0.286 |
| 色 | 0.991837 ± 0.025814 | 0.948104 ± 0.077235 | 0.949 |

この一致は、固定した現代環境の原典参照に対するものである。当時のPython 2の
ビット単位の再現や、論文表と同じ評価条件での一致・統計的同等性を保証しない。
全500反復の全中間状態を照合したという意味でもない。
以前の4機能版との比較は、初期化・乱数・通信等もまとめて変わる比較なので、
個別のヒューリスティクスの効果を分離するものではない。

SINGLE専用の原典は手元にない。SINGLEの原典互換版は、著者からの共通実装という
情報に基づきINTERで確認した初期化・学習処理を適用し、Uの観測語と前処理を維持する。
INTERでの一致をSINGLE原典との一致と読み替えない。

詳しい結果・標準偏差・全物体評価・再実行手順は
[10試行の比較報告](../docs-for-developper/experiments/inter_original_execution_reviewed/report.md)、
対応する設定・保証範囲は
[原典互換版の仕様](../docs-for-developper/original_compatibility_spec.md)を参照。
数理と研究上の採用判断は[著者NOTE](../README.md#author-note)に記す。
